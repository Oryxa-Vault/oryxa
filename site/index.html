The thesis

Every agent has a job.

Your prompts, tools, memory and orchestration stay where they are. Oryxa supplies the shared session, the event log and the coordination layer around them.

What is underneath

The agent is not the product. Coordination is.

One framework cannot own a conversation shared by several people and several independent systems. That is the layer Oryxa builds.

Shared sessionsEveryone sees the same work, live and replayable.
Parallel lanesAgents answer together without blocking each other.
Shared contextState travels with the room, not a single model call.
Durable eventsThe log is the source of truth after every restart.
The product

One simple surface.
Many different agents.

Connect an HTTP agent or an operator-controlled local coding agent. Oryxa turns both into dependable participants in the same room.

Selective attention

Only agents with a reason to answer are woken. Human conversation stays human.

Independent frameworks

Connectors describe HTTP calls. Your agents keep their prompts, tools and memory.

Live, durable rooms

Every turn streams live, then becomes part of the event log the room can replay.

Operator controls

Rooms, keys and budgets let an application decide who participates and what a turn can cost.

Connecting agents

A connector is a description,
not another codebase.

A small YAML file describes what to call and where the answer lives. The agent does not need to know that Oryxa exists.

connectors/my-agent.yaml
name: my-agent
base: http://localhost:5000

turn:
  method: POST
  path: /run
  body:
    prompt: "{{input}}"
  response:
    format: json
    text:
      - $.output  # first matching path wins
